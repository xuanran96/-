# 尚泷 KMES 仓储位置管理 Web 版

独立云端数据空间，初始包含明确标注的示例库位与库存。四个页面通过 `/api/warehouse` 共用 D1 持久化数据。尚未连接原 KMES、企业登录或生产库存。

## 使用闭环

1. 扫码登记：点示例条码或新增商品资料，填写唯一箱号、订单、客单、数量与目标库位后登记；支持云端暂存与恢复。
2. 库位总览/位置查询：筛选后打开详情、定位地图、打印 Code128 库位标签，或选择库存单条/批量移位。
3. 取出与追溯：选择库存生成拣货单，先预留；确认实物拣货后，逐条输入实际条码和数量复核，最终扣减库存。
4. 待拣货任务可取消并释放预留；可调整波次；详情可查看完整任务轨迹和打印拣货单。

摄像头识别依赖浏览器 BarcodeDetector 与摄像头权限，不支持时使用键盘型扫码枪或手输。实物扫码枪、打印机及摄像头需现场验证。Web 版数量按服装成品“件”处理，不支持面料小数单位。初始地图为逻辑格位图，不代表实地路线。

## 本地启动

使用 Node 22.13+；保留 package-lock.json。

```sh
npm ci
npx wrangler d1 migrations apply DB --local --config wrangler.local.json
npm run dev
```

开发服务地址以控制台输出为准。生产部署构建：`npm run build`。数据库定义位于 `db/schema.ts`，迁移位于 `drizzle/`。

## 验证

```sh
npx tsc --noEmit
node --experimental-strip-types --test tests/warehouse.test.ts
node tests/api.test.mjs
```

集成测试只允许 localhost，会在本地测试数据库写入 QA 前缀测试记录；不对生产数据运行。线上部署采用单所有者私有访问，不能直接改为公开或多人共用后作为企业权限系统使用。

## 对接边界

前端操作统一经 `act(action,payload)` 调用后端；领域规则位于 `lib/warehouse.ts`。登记、移位、预留、出库通过 D1 版本比较更新单条状态记录，保证整次操作原子生效，冲突重试时重新校验库存。请求标识防重；箱号独立防重复登记。

当前是独立工作台的数据规模实现，服务端以单一状态记录保存完整仓储数据与轨迹，不适用于无限增长的大型生产库存账。原 KMES 接入时应改用原库存事务、单据和企业身份审计，拆分查询及分页到服务端；不能直接将本应用登记逻辑用于已记账的生产入库单，否则可能重复计入总库存。

库位移位保留箱号的库存明细；当前箱码用于商品识别，取出复核以商品条码与数量核验，尚无整箱唯一复核约束。已拣货任务无法直接取消，避免误释放已取出的实物库存。

发布前保留应用代码与数据库备份。应用回退不能回滚已经发生的库存变化；须通过原单据对账/纠错流程处理。
