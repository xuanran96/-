# 轩 · AI 项目验收与完善

**v0.1.0 · 第一个版本**

给出最终目标，让 AI 检查代码、运行程序、补齐功能、修复问题并持续复测，交付可用结果
和验证证据。本项目提供执行这套流程的 AI 技能、项目模板和自动验收工具，也支持文档、
表格及日常项目的交付验收。

这个项目面向普通使用者。你不需要先理解 PRD、API、数据库或软件工程流程，只要告诉
AI：

> 我想完成什么，谁会使用，什么结果算做好。

AI 将按下面的流程协作：

```text
明确最终目标 -> 做成计划 -> 执行与完善 -> 测试验收 -> 达标交付 -> 可选复用
                                  ^          |
                                  |-- 未达标 --|
```

## 立即开始

下载本仓库，在能读取项目文件、编辑代码并执行命令的 AI 环境中打开它，将目标代码位置
和最终目标交给 AI。无需先手工填写所有模板；AI 应自行调查并整理已有信息。

1. 复制 `templates/project/` 到 `projects/<你的项目名称>/`。
2. AI 根据你的最终目标填写 `01-project-card.md`，明确目标与边界；已有明确要求就直接推进。
3. AI 生成 `02-plan.md` 并推进任务。
4. AI 运行检查，发现缺口后直接完善并复测；达标后填写 `03-acceptance.md`，附上证据和使用方法。
5. 只有发现反复出现的做法时，才创建 `04-reuse-candidates.json`。

如果当前 AI 支持项目技能，可以直接说：

> 使用 `$lightweight-project` 帮我把这个想法作为一个小项目推进。

## 验收代码和程序，并完善到最终目标

可以直接对 AI 说：

> 使用 `$lightweight-project` 验收并完善这个项目。代码位置是 `<仓库地址或本地目录>`。
> 我的最终目标是 `<用户能完成什么，预期结果是什么>`。请检查代码、实际运行程序，
> 补齐缺失功能并修复问题，持续复测到目标达标，交付可用程序、使用说明和验证证据。

AI 会把目标拆成可验证条件，按“检查 → 实现或修复 → 运行 → 回归”持续推进。只有报告、
构建成功或现有测试通过都不足以证明目标达成。遇到真实外部阻塞时明确说明缺什么，
继续其他可执行工作，不把未验证项当作通过。

本项目是 AI 工作流与工具集，需要具备代码编辑和运行能力的 AI 执行完善工作；命令工具
负责检查和取证，本身不会自主调用模型或修改代码。无需安装即可运行示例（Python 3.10+）：

```bash
python scripts/run_acceptance.py examples/software-goal/acceptance-plan.json --root examples/software-goal --run
```

接入自己的项目：复制 `templates/software/acceptance-plan.json`，替换目标、验收条件和
命令，再按 [软件验收与完善](docs/SOFTWARE_ACCEPTANCE.md) 执行。每轮输出独立的 JSON
报告与日志。退出码 `0` 仅表示配置中的自动检查通过，最终还需核对目标覆盖。

## 适合做什么

- 调研、报告、内容和演示材料；
- 活动策划、学习计划和个人事务；
- 表格整理、数据分析和重复工作自动化；
- 业务流程改进和低风险的小工具；
- 已有代码、CLI、网页、API 或桌面程序的目标验收、功能补齐和修复；
- 已经说了很多轮，需要把散落聊天整理成可交付项目。

涉及资金、隐私、生产数据、公共接口、数据库迁移或不可逆操作时，进入相应领域的专业
流程，继续完成已授权的实现与验证；缺少授权的外部操作在执行前处理。

## 项目原则

- 先确认目标和边界，再大规模执行；
- 文档服务于决策，不以文档数量判断质量；
- AI 自己完成能自动完成的测试，使用者做最终业务验收；
- 一次聊天只能形成候选，不能直接包装成成熟技能；
- 账号、密码、密钥、Cookie、隐私和敏感正文不得进入复用资产。

## 备注说明

- 五个高频工程协作 Skill 仍处于历史任务回放阶段；新增软件闭环也不宣称已完成历史回放。
- `满足 3 项` 只表示值得进入候选池，不表示已经具备正式 Skill 的发布质量。
- 模板中的示例文字需要替换为真实项目内容；不适用的栏目可以删除，不保留空占位。
- 项目产物默认使用简体中文，技术标识符、文件名、命令、代码符号和行业通用缩写保留原文。
- 中文标题、标点、数字、英文与空格的统一规则见[中文格式规范](docs/CHINESE_WRITING_STYLE.md)。

## 项目来源

“轩 · AI 项目验收与完善”由 别感冒 发起并维护，使用 Python 实现自动验收与证据
记录工具，并在 GPT-6 Astra 的辅助下完成工作流改良、代码实现和验证。目前版本为
**v0.1.0**，是本项目的第一个版本。

Python 是验收工具的实现语言；GPT-6 Astra 是本版本开发过程中使用的 AI 辅助工具。
使用本项目时，可由具备代码编辑和命令执行能力的 AI 按照仓库流程开展工作，验收脚本
本身不内置或调用该模型。
