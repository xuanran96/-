---

# 目标

定位首个真实失败，修复根因，并证明相关测试和必要回归均通过。

# 必要输入

- 失败命令或 CI 任务、完整日志、代码仓库。优先自行运行并收集，不让用户手工转录可获取内容。

# 执行步骤

1. 用项目声明的命令复现失败，记录环境和首个真实错误。
2. 缩小到最小失败测试，排除连锁错误和日志噪声。
3. 判断根因属于生产代码、测试预期、夹具、时序、依赖还是环境。
4. 读取相关实现和最近变更，用证据确认判断。
5. 做最小修复；只有需求确实变化时才调整测试预期。
6. 先运行最小失败测试，再扩大到相关测试集、构建和必要回归。

# 约束

- 不通过跳过、删除或放宽断言掩盖失败。
- 不把测试通过等同于所有功能正确，报告实际覆盖范围。
- 不覆盖无关工作区修改。

# 输出格式

- 首个真实失败与根因
- 修改内容
- 执行的测试及结果
- 未覆盖范围和剩余风险

# 备注说明

- 测试名称、日志原文和命令保持原样，根因与验证结论使用简体中文。
- 环境性失败与代码失败分开记录，不把重新运行偶然通过视为修复证据。
