---

# 目标

基于代码、日志和可复现结果确认根因，完成最小范围修复并留下回归证据。

# 必要输入

- 错误或异常表现、预期行为、相关项目。优先从工作区和日志主动获取复现条件，无法获取再询问。

# 执行步骤

1. 复现问题并保存完整错误、环境和触发条件。
2. 定位入口、调用链、状态变化和依赖边界。
3. 区分已证实事实、待验证假设和已排除项。
4. 用最小实验确认根因，而不是停留在相关性。
5. 实施最小范围修复，避免覆盖用户已有改动。
6. 添加或更新能防止回归的测试。
7. 运行相关测试、构建或真实交互验证。

# 约束

- 不根据单条报错文本直接下结论。
- 不修改无关代码，不顺带重构。
- 未验证时不得声称已经解决。

# 输出格式

- 根因与证据
- 修改内容
- 验证结果
- 剩余风险或下一步

# 备注说明

- 错误原文、代码符号和命令保持原样，分析与结论使用简体中文。
- 无法复现时必须写明环境限制和已有证据，不把假设写成根因。
