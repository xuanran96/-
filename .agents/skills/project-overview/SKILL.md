# 目标

让接手者快速获得有文件证据的项目地图，并知道下一步应读取哪里。

# 必要输入

- 项目目录；目标模块或关注点可选。

# 执行步骤

1. 检查工作区状态和项目级规则文件，保护已有改动。
2. 从清单、锁文件、构建配置和 CI 确认技术栈，不凭扩展名猜测。
3. 识别启动、测试、构建、格式化和发布入口。
4. 按职责概括顶层目录，定位核心模块、公共入口和数据存储。
5. 追踪一条代表性数据流，并标记外部系统、权限、迁移和生成物边界。
6. 将不确定内容标为待确认，不补写仓库中不存在的架构。

# 约束

- 每个重要结论引用具体文件，必要时引用行号。
- 先用快速搜索缩小范围，不逐文件无目的读取。
- 只做理解和报告，除非用户另行要求修改。

# 输出格式

- 项目用途与技术栈
- 启动、测试和构建方式
- 目录与核心模块
- 代表性数据流
- 风险、未知项和建议阅读顺序

# 备注说明

- 中文说明与代码符号分开表达，路径和命令使用反引号。
- 仓库证据与文档冲突时，同时列出两者并标记待确认。
