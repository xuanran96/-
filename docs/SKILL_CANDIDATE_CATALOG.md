# 可复用场景目录

这份目录用于决定先收集哪些场景，不代表每个条目都已经成熟。首批实现选择覆盖面大、输入
输出稳定且容易验收的五项。这里的“已实现”表示已有可试用 Skill 文件，不表示已经完成
历史回放或达到成熟准入标准。

## 首批已实现草案（待历史回放）

| 场景 | 输入 | 产物 | 核心验收 | Skill |
| --- | --- | --- | --- | --- |
| 项目快速导览 | 项目目录 | 技术栈、结构、启动方式、模块、数据流、风险 | 每个结论都有文件依据 | `project-overview` |
| 报错诊断 | 错误、日志、复现条件 | 根因、修复、验证结果 | 不根据报错文本猜测 | `bug-diagnosis` |
| 代码审查 | 变更范围 | 按严重程度排列的问题 | 每条有文件、行号和影响 | `code-review` |
| 测试失败修复 | 失败测试、日志、代码 | 最小修改和回归证据 | 首个真实失败已复现并修复 | `test-failure-fix` |
| PR 描述 | 差异、提交和验证结果 | 背景、修改、验证、风险、回滚 | 与实际变更一致 | `pr-description` |

## 后续候选

- 代码理解：陌生模块解释、功能调用链追踪、配置项溯源。
- 开发实现：小功能端到端实现、新增 API、新增页面、批量机械修改、依赖升级、数据库变更。
- 问题排查：构建失败、性能分析、线上事故复盘。
- 质量保障：补充单元测试、测试用例设计、安全检查、发布前检查。
- Git 与交付：Commit Message、拆分提交、合并冲突、Changelog。
- 文档沉淀：技术文档、README、接口文档、会议行动项、知识库去重归档。
- 数据办公：Excel 清洗、多表核对、日志统计、文本分类、固定格式报告。

后续条目仍需用真实任务验证，不因为列入目录就批量生成 Skill。

## 备注说明

- “已实现草案”表示结构和基础校验已经完成，不表示已经达到正式发布标准。
- 新增候选前先检查是否能扩展已有 Skill，避免为相同工作流创建不同名称。
- 场景边界差异明显时应拆分 Skill，不通过持续增加条件分支强行合并。
