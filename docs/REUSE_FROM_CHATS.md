# 从聊天和项目中沉淀复用能力

聊天记录容易重复、矛盾并包含隐私，因此它只能提供候选证据，不能直接成为正式技能。

## 提取什么

- 反复出现的场景和触发条件；
- 稳定的输入、操作步骤、输出和完成检查；
- 使用者对错误做法的明确纠正；
- 已验证的模板、工具和命令；
- 失败案例、适用边界和不能复用的内容。

## 第一关：是否值得进入候选池

一个场景满足下面 7 项中的至少 3 项，就值得记录为 Skill 候选：

- 每周或每月重复出现；
- 每次输入结构相似；
- 操作步骤相对固定；
- 有明确产物，例如代码、报告、表格或提交记录；
- 有固定检查项或验收标准；
- 经常需要反复提醒 AI 遵守约束；
- 容易因遗漏步骤导致返工。

下面这些内容不进入候选池：一次性的开放讨论、高度依赖临场判断的架构决策、输入步骤
输出均不稳定的任务，以及单纯润色一句话。

满足“3 项”只代表值得继续收集，不代表已经可以发布为 Skill。

## 第二关：正式技能准入阈值

候选必须全部满足：

| 指标 | 阈值 |
| --- | --- |
| 同类场景出现次数 | 至少 3 次 |
| 独立覆盖范围 | 至少 2 个项目或独立会话 |
| 结构完整 | 触发、输入、步骤、输出、完成检查均明确 |
| 有证据的成功次数 | 至少 3 次 |
| 验证成功率 | 不低于 80% |
| 安全检查 | 密钥、账号、隐私和敏感正文均已移除 |
| 历史回放 | 使用 3 个历史任务回放，能覆盖其中大多数案例 |
| 使用者批准 | 明确同意创建或发布技能 |

成功率计算：`verified_successes / verified_attempts`。没有实际验证的尝试不进入分母，也
不能算作成功证据。

## 状态

- `collecting`：证据不足，继续观察；
- `eligible`：量化阈值满足，等待使用者批准；
- `approved`：使用者已批准，可以进入技能创建；
- `rejected`：不适合复用，记录原因后停止积累。

运行下面的命令可检查候选文件：

```powershell
python scripts/evaluate_reuse_candidate.py projects/<project-id>/04-reuse-candidates.json
```

评分通过不等于自动发布。正式技能仍需独立结构校验和真实场景验证。

## 从真实对话提炼

1. 收集最近 30～100 次真实任务。
2. 删除纯问答、一次性讨论和没有产物的对话。
3. 为每次任务标注用户意图、输入材料、步骤、工具、产物、验收方式和返工原因。
4. 按“意图 + 产物 + 工作流”聚类，不按关键词表面相似度聚类。
5. 同类场景达到 3 次后形成候选；重复提醒写成约束，返工原因写成检查项。
6. 使用 3 个历史任务回放。无法覆盖大多数案例时拆分 Skill，不堆叠条件分支。

使用 `templates/skill-mining/task-inventory.tsv` 登记任务，使用
`templates/skill-mining/skill-candidate.md` 编写候选说明。

## 备注说明

- 候选评分只减少重复判断，不能替代对真实任务证据的审查。
- 同一批聊天可能包含多个不同意图，应拆成多个任务样本后再聚类。
- 涉及个人隐私或敏感业务正文时，只保留脱敏后的事实摘要和来源编号。
