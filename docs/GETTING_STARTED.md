# 如何验收并完善到最终目标

本指南适用于“轩 · AI 项目验收与完善”`v0.1.0`。你提供目标和代码位置，AI 负责调查、
实现、运行和复测。验收工具用于自动检查和保存证据；单独运行工具不会自动修改代码。

## 1. 准备目标和代码

将本仓库下载到本地并在具备文件编辑、命令执行能力的 AI 环境中打开。提供待验收仓库的
地址或本地路径；私有代码需让当前 AI 能访问。运行验收工具需要 Python 3.10 或以上，
目标项目还需要其自身依赖和运行环境。

目标尽量描述用户能完成的行为。例如：

> 我需要一个任务管理程序，能够新增、完成和删除任务；重启后任务仍然存在；空标题要有
> 明确提示。请验收现有代码，补齐这些功能并修复问题，直到这些条件都通过。

无需先告诉 AI 用什么框架。已有技术选型、不能修改的内容或运行限制，一并说明即可。

## 2. 把任务交给 AI

复制下面的提示词，将两处方括号替换为你的内容：

```text
请使用本仓库的 lightweight-project 技能和 docs/SOFTWARE_ACCEPTANCE.md 流程。
待验收代码位置：[仓库地址或本地目录]
最终目标：[用户能完成的操作及预期结果]

请自行调查代码、依赖和启动方式，把目标拆成可验证条件。
检查源码并实际运行程序；发现缺失功能或错误时直接修改实现，补充必要测试并回归。
持续完善到目标达标，不停留在问题清单或建议。
不能删除失败测试、放宽目标或把未验证项算作通过。
遇到必须依赖外部权限、服务或业务决定的阻塞时，说明解除条件，继续其他可推进工作。
最终交付代码、启动与使用说明、逐项验收结论和证据。
```

支持技能调用的环境也可使用 `$lightweight-project`。如果技能未自动发现，直接让 AI
读取 `.agents/skills/lightweight-project/SKILL.md`，并保持本仓库的文档路径可访问。

## 3. AI 实施验收与完善

AI 在目标项目内建立必要记录，按以下闭环推进：

1. **明确条件：** 每个目标对应条件 ID、输入或操作、预期结果和验证方法。
2. **检查基线：** 阅读代码，执行已有测试，真实运行核心流程，记录当前缺口。
3. **直接完善：** 补齐功能、修复根因，保护已有工作区修改。
4. **复测回归：** 验证修复场景和受影响功能；仍失败就继续修改。
5. **交付证据：** 用最终代码版本重新验证，说明启动方式、使用方法和仍待确认的内容。

以任务程序为例，AI 应实际新增任务、标记完成、删除任务，重启后检查数据，并验证空标题。
只检查页面存在或构建成功，不能证明这些目标已经完成。

## 4. 使用自动验收工具

先在本仓库根目录运行自带示例，确认工具能工作：

```bash
python scripts/run_acceptance.py examples/software-goal/acceptance-plan.json --root examples/software-goal --run
```

预期：报告状态为 `automated_passed`，退出码为 `0`，`acceptance-runs/` 中出现本轮
`report.json`、配置快照和日志。示例有 4 项检查，分别验证 0 度、负数、非数字和非有限值。

接入目标项目时，让 AI 复制 `templates/software/acceptance-plan.json`，根据真实目标
填写条件和测试命令。下面的占位路径需要替换，含空格的路径保留引号：

```bash
python scripts/run_acceptance.py "目标项目/acceptance-plan.json" --root "目标项目目录"
python scripts/run_acceptance.py "目标项目/acceptance-plan.json" --root "目标项目目录" --output "验收证据目录" --run
```

第一条检查配置，第二条才执行已审阅的命令。所有检查在 `--root` 指定的代码目录运行。
目标使用虚拟环境时，在配置中填写该环境的解释器路径。完整字段见
[软件验收与完善](SOFTWARE_ACCEPTANCE.md#可执行验收工具)。

| 结果 | 意义 | AI 接下来做什么 |
| --- | --- | --- |
| `automated_passed` / 退出码 `0` | 配置中的自动检查通过 | 核对目标是否完整覆盖，完成实际交互验证 |
| `needs_work` / 退出码 `1` | 程序输出或退出码不符合预期 | 定位、修改代码、重新运行 |
| `blocked` 或配置错误 / 退出码 `2` | 超时、缺少命令或配置不完整 | 诊断并解决环境、配置或程序问题 |
| `needs_review` / 退出码 `3` | 还有人工或交互条件待确认 | 补充实际交互证据或请求必要的业务确认 |

## 5. 怎么判断真正完成

- 最终目标的每项能力都有实际结果和对应证据。
- 核心程序能够启动和使用，适用的异常、边界与回归检查已通过。
- 证据对应交付的最终代码；修改后已经重新验证受影响条件。
- 已交付启动命令、依赖说明、使用方法和验收记录。
- 没有把失败、未执行、环境阻塞或用户尚未确认的条件写成通过。

用户只需核对最终效果及必须由自己决定的业务条件。若有必需条件尚未通过，应继续完善
或标记具体阻塞，不能以“基本完成”代替验收。

## 验证本项目本身

开发者可在隔离环境安装测试依赖并执行：

```bash
python -m pip install -e ".[dev]"
python -m pytest -q
python -m compileall -q scripts
```

首版本地验证为 36 项测试通过，含错误程序修复后复测、超时、中文输出、人工待确认和
逐轮证据保存。Windows、Linux 与 Python 3.10、3.12 的 CI 按仓库实际运行结果判断。
